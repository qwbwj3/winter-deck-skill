# winter-deck：只填数据，不写动画

## 三条底线
1. **不写任何动画、样式或 3D 代码，不改 `runtime/`。** 你只做四件事：拆页、填 JSON、配图、跑脚本。
2. **脚本结果为准。** 校验 0 失败才打包；能看图就必须亲眼看截图。
3. **每按一下，文字和画面一起变。** 每一步的标题是一句新的判断。

`<SKILL>` 指本 skill 目录；命令都在用户的项目目录里运行。

## 第 0 步：环境
- `node --version` ≥ 18，没有就停下，请用户安装 Node.js 18+。
- 交付前必须安装阿里巴巴普惠体 3.0，再重新构建并检查换行；不把字体文件放进仓库。构建提示未找到字体时，成品会回退到系统黑体，不能据此确认最终版式。
- 截图检查需要 Chrome 或 Edge；都没有时，第 8 步改为请用户人工看一遍。

## 第 1 步：拟定页面清单（先不写 JSON）

先读第 3 步的页型规则，按材料拟清单，暂不制作整稿。

材料没有可做 3D 的数据时，默认全用结构页，并告知用户“这份材料没有可用的 3D 数据，按内容关系安排结构页”。不必停下来问是否补数据；补充用户数据或查找带出处的公开数据只作可选项，不为凑页数编造数字。

- “一句判断”是结论（“五角场是离目标最远的店”），不是话题（“门店情况”）。
- **品牌色**：用户提到公司主色或给了色值，确认后在顶层写 `"brand": "#1F6FEB"`；没提不写。
- **用户给的是现成大纲时**：页序照用，页型仍按内容形状选，不要一页对一页塞进要点清单。用户说“标题不要动”就原样放进 `title`，判断写进 `steps[].body`，结论写 `takeaway`；没说就把话题式标题改成判断句，并列出原标题对照。要点清单、表格、关键数字三种加起来超过一半，说明在换皮，回头重选。

## 第 2 步：发给用户确认，停下等回复

把下面四块合在**一条消息**里发给用户，不要分批追问。已明确的选择写成“沿用已确认的……”，不重复问。

### 页面清单

| 页码 | 观众要得出的一句判断 | 内容形状 | 页型（数据页标 3D） | 图片：用什么图、从哪里来 |
|---|---|---|---|---|

逐页填完整：3D 数据页在页型旁标“3D”；图片列写图的具体内容、用户附件名或准备截图的公开网页及出处。不要图的页写“无图”，待补图片写“图位：……，待用户提供/更换”，不可用“大字＋小标签”冒充配图。表后写：**“本份共 N 页，其中 M 页是 3D 数据页”**，N、M 换成实际数。

### 风格

先用用户材料写出能代表内容的 1～2 页 deck JSON：有文字内容就选一页非封面文字页，有 3D 数据就再选一页 3D 页；没有数据不虚构 3D 样章。此时只做选风格样章，不制作整稿。运行：

```bash
node <SKILL>/scripts/style-sample.mjs decks/<名字>-sample.json --out out/<名字>-style-sample
# 使用已有整稿的指定页（页码从 1 起）：
node <SKILL>/scripts/style-sample.mjs decks/<名字>.json --pages 2,3 --out out/<名字>-style-sample
```

不填 `--pages` 时，默认选择第一页非封面文字页和第一页 3D 页。脚本分别构建并截图全部 8 个深浅预设，生成带中文名、英文 id、深浅标记的样章对照图。打开对照图确认内容和版式，再连同推荐理由发给用户选择；不能把脚本成功当作用户已选。只有没有可用浏览器时，才用 `<SKILL>/assets/style-grid.png` 作后备，并说明未做实际内容样章。环境不能发图时写出图片的实际路径；后备图也缺失时明确写“风格图待更新”，不假装已经发图。

按场合推荐下面 1 套并说理由，再列另外 3 套各一句，问用户：**“选哪套？要深色还是浅色？”** 每套都有深浅两版，id 见 `references/presets.md`。

| 风格 | id 前缀 | 场合与构图 |
|---|---|---|
| 发布会 | `keynote` | 产品发布、科技、对外演讲、路演；判断句做主角，大留白，讲到哪项亮哪项。 |
| 杂志报告 | `journal` | 咨询、研究、经营汇报；报头、分栏、来源脚注。 |
| 便签拼贴 | `pinboard` | 培训、复盘、工作坊、头脑风暴；正在讲的那项放大成主卡。 |
| 等轴测图 | `isoplan` | 流程、架构、组织机制、空间类；条目变成模块，结构关系可见。 |

默认推荐规则：按上述明确场合推荐；没有更明确场合时，对外用发布会，对内汇报用杂志报告，培训用便签拼贴。推荐不等于用户已选，仍要等回复。

### 图片

四选一：**不要图片／先留图位、之后自己换／用我给的图／用生图工具生成**（你确实有生图工具时才提供最后一项；已说过的选择不重问）。

教程、工具、操作、产品类题目，优先提议：**“我去公开网页截图当证据图”**，说明截哪些官网、文档或产品页面，在清单标出处，交给用户确认；这作为证据图的获取方案，与上述图片偏好一并确认。不要自行用网上图片替代用户的“不要图片”。截图只取公开页面，记录页面标题、网址和获取日期，保存为本地图片供打包；获取失败则如实说明，不假装已有图片。

### 数据

按现有材料说明实际能安排的 3D 页数；没有数据默认全用结构页，3D 数据页少于 2 页也照实安排，不设最低页数。可选补数据：用户提供数据；或由 Agent 去找带出处的公开数据，须经用户确认，先列出准备找的具体指标、范围和用途。补数据不作为继续制作的前提，不为凑页数编造数字。

时间分配、预算拆分、人数构成等“一个整体分成几份”的数字，必须做成 `share` 等数据页，不准写进目录页或要点。例如 5/25/10/5/15 分钟应作为一页时间占比数据，保留各项名称与分钟单位，目录仅列章节。

**发完停下，等用户回复后再写整稿 JSON。** 回复中仍有影响制作的未决项，先补齐确认，不把用户未回答的选择当作同意。等待期间只保留上述选风格样章，不构建整份演示。

**唯一跳过条件**：用户原话明确说了“不用问我”“全部按默认”或“直接做不用确认”，才可跳过本步。单独一句“直接做”不构成豁免。跳过时按场合选推荐风格，未指定的深浅用浅色、图片用“先留图位”；已有明确选择照用。仍先拟清单并检查图片、数据与页型规则；不编造数据，不自行生成付费图片。在交付时写明：**“按默认：风格 X、图片 Y”**，替换为实际选择。

## 第 3 步：按内容形状选页型

共 31 个页型。**内容是数据形状，就用 3D 数据页**，不要改写成文字。

**3D 数据页**

| 内容形状 | 页型 | 舒服 / 上限 |
|---|---|---|
| 3 项以上可比较的数值（各部门、各门店） | `compare-bars` | 3～6 / 12 |
| 逐层筛掉的环节（转化、审批、AARRR） | `funnel` | 3～5 / 6 |
| 一个指标随时间变化 | `trend` | 6～12 点 / 16 |
| 一个整体拆成几部分（≤6 项、要讲述感） | `share` | 3～6 / 8 |
| 一个可相加的总量数字 | `kpi` | — |

只有两项比较用 `versus` 或 `figures`。成本、离职率、不良率等越低越好的指标，在 `compare-bars` / `figures` / `trend` 写 `better: "down"`。

**2D 版式页**（每页可加 `takeaway`：底部一句结论）

| 内容形状 | 页型 | 舒服 / 上限 |
|---|---|---|
| 开场议程、几条要点 | `points` | 3～5 / 6 |
| 目录、章节过渡（给 `current`） | `chapter` | 3～5 / 6 |
| 2～4 个关键数字，各带一句解释 | `figures` | 3 / 4 |
| 两维四类：SWOT / PEST / 波士顿 / 优先级 | `matrix`（`template`） | 4 格 |
| 多行多列的对比、明细 | `table` | 4～6 行×3～5 列 / 8×6 |
| 问题拆解（A = B × C） | `tree` | 3 支×2～3 / 4×3 |
| 一句要观众记住的话 | `quote` | — |
| 顾客、专家原话 | `testimonial` | — |
| 有先后的步骤 | `flow` | 3～5 / 6 |
| 按时间发生的事件 | `timeline` | 4～6 / 8 |
| 几条线并行的排期 | `roadmap` | 3 道 / 5 道×12 段 |
| 之前/之后、方案 A/B | `versus` | 3 行 / 5 |
| 分层的优先级、战略 | `pyramid` | 4 层 / 5 |
| 首尾相接的循环、飞轮 | `cycle` | 4 / 6 |
| 4～9 个功能并列 | `features` | 6 / 9 |
| 风险、影响和应对 | `risks` | 3 / 5 |
| 团队、分工（2～6 人） | `people` | 3～4 / 6 |
| 结尾：行动、负责人、时间、请决定 | `actions` | 3 / 5 |

**分析模型页**（内容符合模型形状时优先用）

| 内容形状 | 页型 | 上限 |
|---|---|---|
| 2～3 个条件同时满足才成立 | `venn` | 3 个集合 |
| 1～4 个指标的完成度 | `gauge` | 4 |
| 整体拆成 2～8 块、看谁占大头 | `treemap` | 8 |
| 同一对象多维打分或两者对比 | `radar` | 8 维×2 组 |
| 钱/流量/人从来源流向去处 | `sankey` | 3 列×6 |
| 行业竞争格局（五力） | `forces` | 固定 5 格 |
| 先找对问题再找方案（双钻） | `diamond` | 固定 4 段 |

**图文页** `media`：`cover` 封面（必须是第一页）／`evidence` 一张截图＋一个聚焦区域／`reading` 几段文字各配一张图／`gallery` 一段文字＋几张图／`photo` 一张大图＋一句结论。`evidence` 只支持一个 `focus` 矩形，要讲多个区域就拆页。

**节奏**（结合校验器提示，制作时逐条核对）：
- 同一页型不连用；整份里同一种 3D 页型最多 2 次；3D 数据页不连排 3 页。
- 3D 数据页超过 60% 偏多：章节之间插 `chapter`、`quote` 或图片页。
- 不配图的 `reading` 最多占 1/4。
- 材料提到负责人用 `people`，在拆"问题出在哪一支"用 `tree`。
- 大纲是概念类、没有数字时，优先用结构类页型 `tree`、`cycle`、`pyramid`、`flow`、`venn`，不要连续用 `points`、`features` 这类列表页。同一份里列表类页型（`points`、`features`、`actions`）加起来不超过总页数的 1/3。

超过上限不硬塞：合并成"其他"、只留要讲的、或拆成两页。没有合适页型时用最接近的，交付时说明；**不要自己写代码补**。

## 第 4 步：写 deck JSON
写到 `decks/<名字>.json`。整体格式见 `references/deck.md`；**写哪种页，先读 `references/<页型>.md`**（字段、变量、示例）。

- 3D 数据页标题最多 2 行，用 `\n` 断行，每行 ≤13 字。2D 版式页标题写成一行完整短句。
- 3D 数据页里的数字、名称、方向词一律用该页型的模板变量（`{focus.name}`、`{gap}`、`{dir}`），不写死；用户在浏览器里改数据后文字会跟着变。
- 不写"本页展示了…""如图所示"。
- 顶层写 `"title"`（页脚和浏览器标签）、`"preset"`（打开时的风格）、`"presets"`（写全部 8 个深浅预设 id，见 `references/presets.md`）。只打包一份 HTML，不另做明亮版。
- `steps[].notes`：每一步写一两句讲法（用户给了讲稿就用讲稿）。放映时按 N 看，观众看不到。
- 标题里最关键的一个词用 `==` 包起来（`"营收只有 ==74 万元=="`），2～6 字，每个标题最多一处，整份留给真正要记住的词。
- 可选 `"en"`：2～4 个英文词的小标签。整份要么都加，要么都不加。

## 第 5 步：配图（详见 `references/media.md`）
- **证据**（后台截图、报表、聊天记录）：原样使用，不裁不改不调色，用 `evidence`。
- **氛围照片**：给两版 `{"dark": "...", "light": "..."}`。
- 同一组图比例一致（图组 4:3，封面 16:9）。
- **图位**：`{"slot": "门店外立面照片"}`，页面显示占位，用户按 E 换图。证据页用图位时，文字里不要写"原样截图"。
- 没图、没生图工具、用户也不要图位，且未确认使用公开网页截图：不用网上的图，改用版式页。
- 已确认的公开网页截图按证据图使用，保留原图，注明页面标题、网址和获取日期。图位不算已有图片；无图时改清单说明，不能用大字和标签声称已配图。

## 第 6 步：校验
```bash
node <SKILL>/scripts/validate.mjs decks/<名字>.json
```
必须 0 失败。警告逐条处理，不改的在交付时说理由。**不要为了消警告把数据页改成文字页。**

## 第 7 步：打包
```bash
node <SKILL>/scripts/build.mjs decks/<名字>.json
```
生成 `out/<名字>.html`：单个文件，离线可开，图片已嵌入。本机装有阿里巴巴普惠体 3.0 时，会把用到的字裁出来嵌进文件，别人电脑上打开字形一致；没装就用对方电脑的系统黑体，构建时会提示。提示"被人改过"时，先做下面的"修改已有演示"，不要加 `--force`，除非用户明确要丢弃那些修改。

## 第 8 步：截图检查
```bash
node <SKILL>/scripts/snap.mjs out/<名字>.html --check --out out/<名字>-check
```
从 `contact-01.png` 起逐张打开，**亲眼看每一步**：文字有没有压在物体或别的文字上、有没有大片空白或物体出画、图片和这一步的文字对不对得上、浅色风格下字够不够清楚。报告里的"失败"必须修，修内容（缩短文字、换页型、拆页），不改运行时。
- 不能看图的模型：如实告诉用户"未做视觉复核，请打开文件逐页看一遍"。
- 沙箱里只能软件渲染时，地面条纹、发光偏弱多半是渲染造成的，不要据此改数据，交付时说明。

静态截图不能验证播放过程。还要检查：3D 入场未结束时翻到下一页，镜头不会被旧页拉回；按一次推进一步，长按不连跳，编辑时方向键不翻页；树状图按层出现，高亮与讲解顺序一致。可用交互回归脚本检查构建后的文件：
```bash
node <SKILL>/scripts/playback.mjs out/<名字>.html --out out/<名字>-playback.json
```
该脚本使用独立浏览器检查按键、分层显示、切换高亮时的位置和连续帧变化，不替代截图视觉复核。

## 第 9 步：交付时告诉用户
- 双击 `out/<名字>.html` 用 Chrome 或 Edge 打开。→ / ← 翻页（翻页笔可用），P 切深浅，T 换风格，Q 切画质。
- F 全屏放映；N 打开演讲者备注窗口，拖到自己的屏幕上，会议时只共享演示窗口。页面上平时不显示快捷键提示，打开时显示几秒；按 ? 或 H 可再调出。
- E 编辑：直接改字，右侧面板改文字、换图、改数据；⌘S（Windows 为 Ctrl+S）保存回同一个文件。编辑时新打的字如果原文件里没有，会先用系统字体显示，重新打包后统一。
- **实际预设 id**：从本次构建输出的 HTML 读取 `slide-data` 的 `preset`，并与 `style-presets` 中的 id 核对，再报告实际使用的 id、风格名、深浅与选择理由（附本次样章对照图；没有可用浏览器时才附后备 `<SKILL>/assets/style-grid.png`）。不凭记忆写，不把计划中的预设当作实际预设。
- **实际页面与素材**：从构建输出核对总页数和 3D 数据页数；逐页列图片来源（用户附件名／公开页面标题、网址和获取日期／生成图），图位单列页码和待补内容，不算作已配图。
- 说明哪些页用了替代页型、哪些警告没处理、是否做过视觉复核。跳过确认的，还必须写“按默认：风格 X、图片 Y”。

## 修改已有演示
用户在浏览器里改过并保存了 `out/<名字>.html`：
```bash
node <SKILL>/scripts/extract.mjs out/<名字>.html
```
修改和新换的图会提取回 `decks/<名字>.json`（已存在时写成 `.edited.json` 并列出改动）。在提取结果上改，再走第 6～8 步。**不要从旧 JSON 直接重新打包，会覆盖用户的修改。**

## 常见错误
- 数据页标题写死数字或"增长/下降" → 改用变量。
- 为了压 3D 比例把漏斗、趋势写成文字 → 改回数据页。
- 一半以上是不配图的文字 → 换成版式页。
- 版面文字超长 → 按 references 的字数上限缩短。
- 明亮模式照片不适配 → 补适用的 light 版；原生暗调照片可换深色预设或换图，不强行提亮。
- 自己写 CSS/JS 美化 → 禁止。
