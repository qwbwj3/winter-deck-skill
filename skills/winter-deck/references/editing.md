# editing · 编辑后继续填数据

> 独立 Skill 版：31 个页型：compare-bars、funnel、trend、share、kpi、media、chapter、figures、matrix、quote、flow、timeline、versus、points、features、actions、risks、people、testimonial、table、roadmap、tree、pyramid、cycle、venn、gauge、treemap、radar、sankey、forces、diamond。8 个预设：keynote-dark、keynote-light、journal-dark、journal-light、pinboard-dark、pinboard-light、isoplan-dark、isoplan-light。命令里的 `<SKILL>` 换成 Skill 绝对路径，在用户工作目录运行。5 份示例及全部引用图片在 examples/，使用时复制其中的内容到工作目录。

## 在演示里修改

1. 打开整份演示 HTML，按 **E** 进入编辑。左侧选页，右侧改文字、数据和图片；也可直接点页面上的可编辑文字。
2. 标题保留成对的 `==关键词==` 和原有 `{变量}`；把变量改成固定数字后，图表更新不会带着文字重算。标题每行 ≤13 字。
3. 数量、重点、同形版式和本页强调色按页型提供，仍须遵守对应页型容量；调整后检查步标题与实际强调的内容。
4. 按 **⌘S / Ctrl+S** 保存。支持直接写入文件的浏览器首次会要求选择目标文件；不支持时下载新 HTML，应以下载的新文件为准。
5. 按 **Esc** 退出编辑；文字仍在输入状态时可能先结束输入，再按一次退出。退出、换图成功或页面刷新都不等于保存成功。

## 换图

- 在右侧图片栏选对应位置并换图；`{ "slot": "说明" }` 会被实际图片引用替换，不会自动生成深浅双版。未替换图位必须保留待补说明，不能当成真实证据。
- `{ "dark": "…", "light": "…" }` 图片只替换当前深浅版；单一路径在两种模式下共用。先切到目标模式再换图。
- 核对裁边、说明和证据截图的原图比例、聚焦范围。非证据照片可能被压缩；证据截图不走照片压缩，仍需检查清晰度。
- 人物头像不能用图位，暂无素材可省略 `image`，显示名字首字。

## 修改数据前先提取

拿到人工编辑并保存的 HTML 后，先提取，再修改实际输出的 JSON。不要拿旧数据重新生成，覆盖人工改动。

```bash
node <SKILL>/scripts/extract.mjs out/季度复盘.html
```

默认输出 `decks/季度复盘.json`；已存在时另存为 `.edited.json`，再次重名用 `.edited-2.json` 等。以命令返回的实际文件名为准。指定输出也默认另存：

```bash
node <SKILL>/scripts/extract.mjs out/季度复盘.html --out decks/季度复盘-人工修改.json
```

只有明确决定覆盖目标时才加 `--force`。提取报告列出逐页字段变化；没有基准文件时只能说明提取到了哪些内容，不能断言都是人工新改的。

## 必须保留

| 内容 | 处理方式 |
|---|---|
| `component`、数量、重点、`accent` | 以提取后的值继续工作，不能还原成旧稿。 |
| 原始标题标记、`en`、模板变量、备注 | 保留原文；步骤备注优先，页面备注只用于第一步。 |
| `_more` | 保留隐藏条目、隐藏图片引用和换版式信息，不拿来当可见内容。 |
| 已换图的图片引用 | 使用提取后的路径；新图会恢复到本地图片目录，重名另存，不覆盖已有图片。 |
| 尚未替换的图位 | 保持对象形式；说明文字不是图片路径。 |

减少数量会隐藏尾项，增加时优先恢复；换版式会暂存不兼容数据。跨数据页型切换后，原模板可能暂时变成当时显示的文字，**不会随新数据自动更新**，继续改数值前必须核对。关键数字无法转成仪表量程时，该换版式选项不可用。

已有内嵌的隐藏图片可随保存与提取保留；缺失素材的引用仍可能留下，不能承诺图片一定可恢复。提取失败时不要猜写丢失内容，应使用完整保存的新版 HTML。

## 示例

示例数据：提取后继续修改的一页行动计划；隐藏的备选条目仍保留，画面只显示当前一项。

```json
{
  "component": "actions",
  "eyebrow": "示例数据",
  "title": "先统一报修入口",
  "accent": "neutral",
  "items": [
    {"action": "试行单一入口", "owner": "设备主管", "due": "下周五", "detail": "先覆盖包装车间"}
  ],
  "notes": "确认值班人员能够接收通知。",
  "_more": {
    "items": [
      {"action": "扩展到其他车间", "owner": "运维经理", "due": "试行后", "detail": "按试行反馈决定"}
    ]
  }
}
```
